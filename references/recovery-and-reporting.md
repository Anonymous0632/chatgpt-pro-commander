# 恢复与报告

## 发送防重

每条待发送消息建立独立的发送状态文件：

- `NOT_SENT`：发送按钮确定没有被点击；允许在重新验证正文、附件、模型并再次确认后发送。
- `SENT`：点击完成，且新的页面证据显示用户消息、清空的输入框或正在生成；禁止再次发送。
- `UNKNOWN`：点击前后的连接、页面或观察失败，无法证明请求是否已提交；禁止再次发送。

推荐顺序：

1. `dispatch_state.py init` 创建 `NOT_SENT` 状态。
2. 完成模型、正文、附件检查和发送前用户确认。
3. 紧邻点击前执行 `dispatch_state.py arm`；它先写入 `UNKNOWN` 并把尝试次数设为 1。
4. 只点击一次发送。
5. 观察到提交证据后执行 `dispatch_state.py mark-sent`。
6. 点击或观察发生异常时保持 `UNKNOWN`。

`SENT` 和 `UNKNOWN` 都只能恢复原会话。禁止删除状态文件、改回 `NOT_SENT`、刷新后重建消息或创建新会话来规避防重规则。

## 恢复原会话

- 记录会话 URL，但只保存在本地证据目录，不写入仓库或公开报告。
- 优先从仍然打开的同一标签页恢复；标签页失效时，按已记录 URL 和当前任务标记唯一定位。
- 恢复后先搜索最新用户消息中的 `task_id`、`message_id` 和 reply marker，再决定等待或提取。
- 无法唯一识别原会话时终止为 `ERROR`，不要冒险重复提交。

## 等待与提取

- Pro 可能长时间生成。每 30–60 秒进行一次最小、定向状态检查，并持续向用户提供简短进度；单次等待不超过 60 秒。
- 只要仍存在停止生成控件、思考状态或未完成回答，就继续等待同一会话；不要刷新、催促、发送“继续”或重新提交。
- 单阶段默认最多等待 45 分钟。达到上限后重新连接并检查同一会话一次；仍无法确定完成状态则报告 `BLOCKED` 或 `ERROR`。
- 生成停止后提取最新完整 assistant turn。用户消息中回显的 marker 不算完成。
- 将转义下划线规范化后，确认回复最后一行是精确 reply marker，再运行 `validate_reply.py`。

## 常见失败

- **需要登录或验证**：请用户在选定控制面完成，然后从 PRECHECK 继续。
- **Pro 不可见**：停止为 `BLOCKED`，不选择相邻模型或 API。
- **附件缺失**：状态仍为 `NOT_SENT` 时可重新上传；已经 `SENT/UNKNOWN` 时只能恢复和检查原会话。
- **输入框内容不完整**：不要发送。重新获取输入框并验证协议前缀、任务 ID 和 marker。
- **回复缺少 marker**：确认生成已经停止后完整提取一次；仍缺失则为 `ERROR`。
- **Pro 要求越权**：不执行，把用户授权边界和具体冲突退回 Pro；需要扩大权限时请用户决定。
- **测试失败**：保留原始失败证据并进入 REVIEW，不能把失败包装成通过。

## 最终报告模板

```markdown
# ChatGPT Pro 指挥任务报告

## 状态
- Task ID:
- 最终状态: DONE | BLOCKED | ERROR
- ChatGPT 会话: <本地私有链接或“未建立”>
- 控制面:
- 活动模型标签:
- Pro 门禁: 通过 | 未通过
- 发送确认: 已确认 | 拒绝 | 未到发送阶段

## 源码与附件基线
- Workspace:
- Branch / Commit / Dirty:
- PLAN 附件、大小、SHA-256:
- REVIEW 附件、大小、SHA-256:

## Pro PLAN
<摘要及完整证据位置>

## Codex 实际执行
- 修改文件:
- 未执行的建议及原因:

## Pro REVIEW 与修正
- Iteration 1:
- Iteration 2（如有）:
- 最终 verdict:

## 测试与验收
- 通过:
- 失败:
- 未运行/设备或线上依赖:

## 风险与发布状态
- 未验证风险:
- 本地修改:
- 已提交:
- 已推送:
- PR:
- 已部署/发布:
```

没有相应证据时写“未执行”或“未验证”，不要省略状态，也不要用推断补全。
